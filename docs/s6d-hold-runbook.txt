--hold means one argument and only that argument
  wd24s6d-mmap --hold
It always opens /dev/fb0. There is no form that selects another device.
wd24s6d-mmap --hold /dev/fb0
and
wd24s6d-mmap /dev/fb0 --hold
are argc 3. The tool prints
  usage: wd24s6d-mmap [/dev/fbN | --hold]
and returns 1 before open. wd24s6d-mmap /dev/fb0 is the normal path:
it munmaps, closes, and prints "WD24S6D-MMAP ok stamps 5 tail 1".
That is not this test.

Order inside --hold (wd24s6d-mmap.c main)
  alarm(20) is armed before open.
  open /dev/fb0, check fix id wd24s6d and line length 640, mmap.
  The same touches and stamp read-back as the passing run.
  No stdout line is printed for a good stamp check.
  Only after bad==0: printf "WD24S6D-MMAP hold", fflush, alarm(60)
  which replaces the 20 s alarm, then pause().
  The fd stays open and the mapping stays up across that pause.
  "WD24S6D-MMAP ok stamps" is not printed on this path.

The PID line is not readiness. Kill only after the exact line
  WD24S6D-MMAP hold
and only with the decimal PID from echo, typed as digits.
kill -9 does not pull a task out of mutex_lock, console_lock, or a
fault that has not returned. Those waits are uninterruptible.
pause() is interruptible, so a kill sent after the hold line is the
case this sequence is allowed to use. If that kill does not return,
stop. Do not send another kill as a remedy.

If the hold line is absent, the 20 s alarm may already have called
_exit(2) during the stamps. That is not the SIGKILL case. Stop.
If 60 s pass after the hold line with no kill, alarm calls _exit(2).
That is also not the SIGKILL case. Stop and do not record it as one.

What SIGKILL reaches, once the process is in pause()
  Kernel exit unmaps the VMA first. s6d_vma_close only clears the
  driver's VMA pointer. It does not end the banking session and it
  does not unregister the framebuffer.
  Kernel exit then closes the fd. s6d_fb_release(user=1) sets
  stopping, calls s6d_end_locked("fb release"), and clears busy.
  The banking session ends there. It does not stay active until the
  trial expires.
  The framebuffer stays registered until trial expiry, "text", or
  rmmod. Those call s6d_stop, which unregisters. s6d_end_locked
  returns immediately if active is already 0, so expiry does not
  print a second "S6d: end (trial expiry)" after a successful release.
  The trial mode itself stays until expiry. Expiry prints
  "live trial expiry: 0" on success and sets in_text.

s6d proc fields are only the ones s6d_read prints:
  armed active stopping busy fb_reg node
  fbcon_param bind_param
  faults switches thrash latched mapped_base
  why
After release and before expiry, the code leaves armed 1, active 0,
stopping 1, busy 0, fb_reg 1. mapped_base is cleared to all-bits-one.
faults/switches/thrash are not zeroed by release. latched is cleared
by the thrash reset inside end. node is whatever register printed.
After expiry, armed 0 and fb_reg 0. /proc/fb empty is the registration
check. Do not require node to become -1; unregister does not clear it.
