XKB payload for the existing Xfbdev. The X binary and the module
were not rebuilt. This file is not a framebuffer proof.

The server is xorg-server 1.14.7 kdrive. Core keyboard init calls
XkbCompileKeymap. That returns false when xkbcomp's exit status is
not 0. devices.c then calls FatalError("Failed to activate core devices.").
The compiled-in paths are:
  /tmp/xfb-prefix/bin/xkbcomp
  /tmp/xfb-prefix/share/X11/xkb
Default components, from this server's libxkbfile reading rules/evdev
for model pc105 and layout us:
  keycodes evdev+aliases(qwerty)
  types complete
  compat complete
  symbols pc+us+inet(evdev)
  geometry pc(pc105)
There is no command-line switch in this binary that changes the
xkbcomp path. -xkbdir can change the data directory. The payload uses
the compiled-in paths, so the command line does not need -xkbdir.

The sentence "Errors from xkbcomp are not fatal to the X server" is
the -eml string in xkb/ddxLoad.c. xkbcomp prints it. A warning still
exits 0. A missing compiler exits non-zero, and that is fatal.
