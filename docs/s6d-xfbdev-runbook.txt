What was checked offline, against this driver and linux-6.18.57
fb_chrdev.c / fbcmap.c / fbmem.c, and against xorg-server 1.14.7
hw/kdrive/fbdev/fbdev.c.

The fb is PSEUDOCOLOR, packed 8 bpp, 640x480, line length 640, id
wd24s6d. smem_len is the visible frame, 75 pages. There is one mmap.
A second mmap returns -EBUSY. screen_base is NULL. Xfbdev mmaps
fix.smem_len once and keeps a RAM shadow (shadowUpdatePacked memcpy
from that shadow into the mapping). It does not call the kernel
copyarea. The noop copyarea does not block this process.

FBIOPUT_VSCREENINFO with no fb_check_var returns success and leaves the
current mode (fbmem.c). fbdevEnable requires that ioctl to succeed. It
does, and the mode stays 640x480x8.

FBIOPUTCMAP returns -EINVAL. fb_setcolreg and fb_setcmap are absent
(fbcmap.c). fbdevPutColors calls FBIOPUTCMAP and ignores the return.
fbdevEnable programs a colormap only for DIRECTCOLOR. Missing
fb_setcolreg does not stop this binary from starting. The DAC is left
as it already is. Colors are not a pass criterion. A later color change
would be fb_setcolreg under hw_lock, writing 3C8/3C9 the way the
existing DAC save/restore does, with X's 16-bit channels shifted to the
6-bit VGA DAC. That change is not in this tree.

The thrash latch counts consecutive window switches and resets when a
fault stays in the current window. The default bound is 32. A forward
memcpy faults into the next window and then stays there. A single
instruction that touches two windows alternates, and the latch stops
that at 32 and the fault returns SIGBUS. The stamp test wrote single
bytes. It does not show that an X shadow paint will stay under the
bound. Do not raise s6d_thrash_bound. A thrash line is a fail and a
stop. Do not retry.

s6d_bind=0. fbcon does not bind. X is the user open. The bind=1 pass
already returned to VGA text. This run does not bind fbcon at the same
time as X. The trial cannot be turned off. It starts at insmod and
ends the session even if X is still mapped. Kill X before that. kill
does not interrupt mutex_lock, console_lock, or a fault that has not
returned. The latch makes an alternating fault finite, then SIGBUS.
That is not the same as kill breaking the wait.

Xfbdev also opens a free VT and issues KDSETMODE KD_GRAPHICS. That
ioctl is fatal to X if it fails. On the way out it sets KD_TEXT. The
mmap tool did not do this. If the expiry line is not 0, stop. The
picture on the panel is not the pass.

This binary was not executed. Checks that were run: ELF 80386,
static-pie, no INTERP, objdump cmov count 0. Three `pause` (`f3 90`)
encodings are in musl pthread_rwlock. The mmap tool that already ran
on this machine does not contain that encoding. Intel documents `pause`
as a NOP on IA-32 processors older than the Pentium 4. This 486 has
not executed those bytes. If X dies with SIGILL, that is a fail. The
shell can still record it, because X is backgrounded, and the trial
expiry is still the text restore.
