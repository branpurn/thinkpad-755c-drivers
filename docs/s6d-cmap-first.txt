## Stop rules

One phase per approval. A pass does not start the next phase. A failure
stops the series. Do not retry a failed open or a failed PUT. Do not add
`s6d_cmap=1` during phase 1. Do not call `FBIOPUTCMAP` during phase 2.

Before any command: a person is present, `/proc/fb` is empty, and
`sha256sum` of the file about to be loaded matches the hash named for
that phase. The candidate name inside the module is still `wd24adv`.
Do not overwrite the baseline file with it.

## Phase 1 — default off

Load the candidate only, with the existing S6d parameters and without
`s6d_cmap` (the default is 0).

Go: hash is `92591b1e`, `/proc/fb` is empty, and this phase was named.
No-go: any other hash, `/proc/fb` not empty, or no person.

Expect the same text-restore shape as the baseline runs: trial expiry
`in_text 1`, empty `/proc/fb`, `rmmod` 0. `/proc/wd24adv/s6d` includes
`cmap_param 0 published 0 frozen 0`. `FBIOGETCMAP` is `-EINVAL`. This
phase does not prove colours. It checks that the default does not add a
colormap program.

Stop after rmmod. Do not continue.

## Phase 2 — publish read only

A later approval must name `92591b1e` and the words "phase 2".

Same parameters plus `s6d_cmap=1`. Open the fb once. Do not run a client
that issues `FBIOPUTCMAP`.

Go: phase 1 passed on this same file, and the new approval names phase 2.
No-go: phase 1 was skipped or failed, or the hash differs.

Expect one of two results. Open succeeds and the proc line shows
`published 1`, `busy 1` while the fd is open, and `busy 0` after close.
Or open fails, `busy` stays 0, and `failed`/`nmismatch` latch so a second
open is refused. On that failure, stop. The publish read writes `3C6=FF`
and `3C7=00` before it compares. It does not write colour RAM. Let the
trial expire and rmmod. Do not PUT.

## Phase 3 — one set

A later approval must name `92591b1e` and the words "phase 3".

One `FBIOPUTCMAP`, then one `FBIOGETCMAP`, then close and let the trial
expire.

Go: phase 2 on this same file published and closed cleanly, and the new
approval names phase 3.
No-go: publish did not happen, or this is the same sitting as phase 2
without a new approval.

A GET that returns the 16-bit values just written is the kernel cache.
It is not a live DAC read. A GET of `-EINVAL` after an error means `len`
was cleared. Do not treat either result as a panel colour. Do not issue
a second PUT.

## Still not proved

Panel hue, a fifth square, glyphs, the keyboard, and any claim that the
755C DAC matches the host VGA model. The lifetime replay and the VGA
model are host tests. AddressSanitizer showed the rejected free is a
heap use-after-free in that host process. It did not run on the 755C.
